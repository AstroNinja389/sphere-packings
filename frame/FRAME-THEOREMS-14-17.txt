WHAT IS PROVED AND HOW IT ENTERS
A "frame" is a class modulo 2L with n pairs of squared length below 9/4 (minimum 1). The frame theorem of the dimension
says: if the lattice is denser than the frame complement, the n shortest pairs of such a class satisfy
      sum max(|x|^2, 2) > 2n + S0.
The audit program frame/audit_frame_bound.py adds this floor to the class budget (the "frame case" described in its
header) and reports the maximum of the audited density and the frame complement. In both dimensions the audited
density is the larger one.
The proofs are the premise files, bound into the bundles by hash:
   frame/n14/r1/FRAME-PREMISE-n14-v2.txt   (floor 5/8; it takes the unchanged steps from FRAME-PREMISE-n14-v1.txt, floor
                                            1/2, which is in the same folder)
   frame/n17/r1/FRAME-PREMISE-n17-v1.txt   (floor 11/25; steps 1, 3, 4 are those of frame/n14/r1/FRAME-PREMISE-n14-v1.txt)
Outline: n near-orthogonal vectors of one class span a perturbed copy of D_n inside sqrt(2) L; the index of that copy
is the order of a finite "glue" group G; the sum of psi(g) = sum_i cos(2 pi g_i) over G is non-negative; elements of
order two have psi <= 14 - 16 (dimension 14) or <= 17 - 16 (dimension 17); for all other elements a computer-checked
"hybrid lemma" bounds psi from above (below -1 in dimension 14, below -9/20 in dimension 17). This bounds |G|, hence
the density. In dimension 17 the argument starts from an a priori bound for |G|, see "Dependencies".

THE HYBRID LEMMAS AND THEIR RECORDS
Statement (n; range): for Q' = I + diag(delta) + E with delta_i in [0, 1/8], sum delta_i <= range, |E_ij| <= (delta_i +
delta_j)/2:  N(q) >= 2 and N(2q) >= 2 imply psi(q) < claim,  where N is the least value of Q' on a class modulo D_n.
   n = 14, range 5/16, claim -1:    13,160 (case, cell) pairs = 13,145 by the one-class statement + 15 by the two-class
                                    statement (15 x 9 = 135 combinations with 2q), 0 not covered
   n = 17, range 1/4,  claim -9/20: 13,160 pairs = 12,510 by the one-class statement + 650 by the two-class statement
                                    (650 x 9 = 5,850 combinations with 2q), 0 not covered
Records here: the logs of the runs (frame/n14/chain-n14-wide-v1.log, frame/n17/chain-n17-final-v1.log), the bookkeeping
files (FU1-BOOKKEEPING-*.json, HYBRID-BOOKKEEPING-*.json: result COMPLETE in both dimensions), and the hash lists of the
runs (SHA256SUMS-FRAME-n14-wide-v1.txt, SHA256SUMS-FRAME-12-17-v2.txt; they name files of the working folder, most of
which are not in this repository).
The premise texts say that the lemma counts as checked only if the log contains certain lines. They are there:
   frame/n14/chain-n14-wide-v1.log:   "det: DETERMINANT LEMMA n = 14, sum of positive excess <= 5/16: PASS"
                                      "RESULT COMPLETE: n=14 claim -1: 13145 pairs by the one-class lemma, 15 by the two-class lemma, 0 not covered"
   frame/n17/chain-n17-final-v1.log:  "A PRIORI INDEX CAP 79"
                                      "RESULT COMPLETE: n=17 claim -9/20: 12510 pairs by the one-class lemma, 650 by the two-class lemma, 0 not covered"
   (the premise of dimension 17 quotes the last line as "claim -0.45"; the log prints the same number as -9/20).
Lines "RESULT FAIL" and "RESULT INCOMPLETE" earlier in the logs are intermediate. In dimension 14 the 15 cells that the
one-class re-check did not confirm are the 15 pairs passed on to the two-class statement. In dimension 17 the re-check
did not confirm 13 of the 5,863 two-class cell files; the 5,850 confirmed files cover all 650 x 9 combinations. The
bookkeeping program counts a combination only if a re-check confirmed it with no failure, and reports COMPLETE only
if every pair is covered.
Programs (frame/lemma-programs/, byte-identical copies of the programs named in the logs' hash lists; they need numpy,
scipy and python-flint): first programs frame_u_scheme_v1.py, frame_u_scheme_v2.py, frame_u2_scheme_v1.py with
frame_u2_cells_batch_v2.py; re-checks (second implementation, ball arithmetic) frame_u_recheck_v1.py,
frame_u_recheck_v2.py, frame_u2_recheck_v2.py with frame_u2_recheck_cells_batch_v2.py; bookkeeping_fu_v2.py,
bookkeeping_hybrid_v1.py. The arguments of each run are in the premise texts.

WHAT A REPLAY FROM THIS REPOSITORY REPRODUCES
   python -B frame/audit_frame_bound.py frame/n14/r1/bundle.json my-n14.json
   python -B frame/audit_frame_bound.py frame/n17/r1/bundle.json my-n17.json
   python -B joint/audit_joint_bound.py joint/n17/bundle.json my-n17-joint.json
   python -B frame/check_det_n_v1.py 14 5/16
   python -B frame/check_det_n_v1.py 17 1/4
   python -B frame/n17/check_apriori_n17_v1.py
These reproduce: the exact audits (the Fourier function, the joint kernel, the class budget with the frame case, the
two densities and frame complements; reference outputs audit.json in each folder), the determinant checks and the a
priori index cap. Each takes seconds. All six were run from this repository copy on 18 November 2026 and agree with
the stored outputs.
WHAT IT DOES NOT REPRODUCE: the hybrid lemmas. Their certificates (one table of 13,160 rows per dimension, 96 + 135 cell
files in dimension 14, about 5,900 cell files in dimension 17) are NOT in this repository; only the logs, bookkeeping
files and programs are. Regenerating them with the programs took about half an hour in dimension 14 and takes
several hours in dimension 17 on one core. The programs in frame/lemma-programs were not run again from this repository copy. The
numerical search that proposed the multipliers is not here either; it is not part of the proof.
Files named in the premise texts that are not in this repository: price-v3-n14.log (a floating-point pricing, not part
of the proof); the records of the earlier run at range 1/4 in dimension 14 (chain-n14-hybrid-v1.log,
HYBRID-BOOKKEEPING-N14-D1_4-T-1.json, frame_u2_recheck_v1.py, make_frame_u2_recheck_v2.py): the run at range 5/16 kept
here covers every (case, cell) pair anew and its statement contains the one at range 1/4.
